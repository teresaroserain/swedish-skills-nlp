\section*{How to use this file}
Red blocks preserve claims or methods currently present in
\Code{cas-sc-template.tex}. Cyan blocks are proposed replacements grounded in
the executed academic-v2 scripts and the validated result files. This document
does not silently delete earlier review markup. Exact normalized macro $F_1$ is
the confirmatory metric; containment is a pre-declared secondary boundary-relaxed

\section{Metric framing and HPO objective}
\begin{OldBlock}
Containment is treated as the primary measure. The boundary-relaxed
containment macro $F_1$ served as the validation objective and the primary
cross-configuration metric. Optuna returned exact matches plus containment
matches.
\end{OldBlock}
\begin{NewBlock}
Exact normalized macro $F_1$ was the validation objective and the primary
confirmatory metric. Boundary-relaxed containment macro $F_1$ was reported as
a secondary measure of boundary sensitivity. Lexical and semantic matching
were supplementary diagnostics and did not affect hyperparameter selection.
For each of the 36 supervised configurations, Optuna executed 20 trials with a
TPE sampler seeded at 13. The random-number generators were reset immediately
before every trial-specific model initialization and before final training.
\end{NewBlock}

\section{Normalization and one-to-one matching}
\begin{OldBlock}
Exact duplicates and longer phrases containing an already retained shorter
skill were canonicalized to a single item. Matching used a greedy cascade in
prediction order, and containment accepted either normalized string when it
contained the other.
\end{OldBlock}
\begin{NewBlock}
Normalization applied Unicode NFKC normalization, whitespace and dash
harmonization, delimiter cleanup, case-insensitive comparison keys, and
normalization-aware exact deduplication. It did not replace a longer skill with
a nested shorter skill. Predictions and gold items were matched one-to-one in
a fixed cascade. At each level, a deterministic maximum-cardinality bipartite
matching allocated all eligible pairs before the next level began. The levels
were exact equality, contiguous-token containment, lexical similarity, and
semantic similarity. Hence, prediction order could not consume a gold item
that had an exact match elsewhere.
\end{NewBlock}

\section{Inter-annotator agreement}
\begin{OldBlock}
The paper states that both annotator lists used the same surface processing as
model output, that one-to-one exact and containment pairs produced the current
table, that containment was the primary reliability measure, and that the
exact--containment difference reflected boundary variation rather than skill
identification disagreement. It further interprets values between 0.7 and 1 as
``substantial consistency.''
\end{OldBlock}
\begin{NewBlock}
To retain one shared metric definition, Section~\textnormal{Task Formulation
and Key Evaluation Approaches} should define two generic normalized mention
sets $\mathcal{A}$ and $\mathcal{B}$ and let $T$ be the number of
one-to-one pairs assigned under a named matching rule. Equation~\textnormal{1}
then applies without treating either human annotator as ground truth. For model
evaluation, $\mathcal{A}$ is the prediction set and $\mathcal{B}$ is the
gold set; for inter-annotator agreement, the labels ``annotator 1'' and
``annotator 2'' are only a computational orientation, and the resulting $F_1$
is symmetric.

Pairwise mention-set agreement was recalculated on the 32 shared
software-developer advertisements and 35 shared journalist advertisements.
Annotator cells were parsed with the bracket-aware delimiter rule used during
dataset processing. Both lists received the same Unicode, whitespace,
punctuation, technology-spelling, and exact-deduplication normalization used by
the academic-v2 scorer. Prediction-only fragment stopwords, blacklists,
prefixes, and allowlists were not applied to human annotations. Exact pairs
were assigned first by deterministic maximum-cardinality bipartite matching;
contiguous-token containment pairs were then assigned only among the remaining
items. Counts were pooled over each domain--label overlap sample before
precision, recall, and micro $F_1$ were calculated.

Exact agreement is the confirmatory column and containment is a secondary view
of boundary sensitivity. Their difference is consistent with boundary
variation but can also include differences in semantic scope, so it should not
be attributed exclusively to boundaries. Pairwise mention-set $F_1$ measures
observed overlap and is not a chance-corrected coefficient such as Cohen's
kappa; therefore, kappa-style qualitative bands such as ``substantial'' should
not be assigned to these values.
\end{NewBlock}

\section{Data processing and splitting}
\begin{OldBlock}
The manuscript describes a grouped 40/10/50 split and states that grouping
prevents the same advertisement from crossing partitions. It also reports the
pre-parser-correction label counts.
\end{OldBlock}
\begin{NewBlock}
The corrected corpora contain 315 software-developer advertisements, 322
journalist advertisements, and 637 records in the merged corpus, each with a
unique identifier. All five annotation fields were parsed with a bracket-aware
delimiter rule so commas inside matched brackets were retained inside one
skill phrase. For each domain--skill configuration, identifiers were assigned
to 40\% train, 10\% validation, and 50\% test using seed 13. The balancing
objective used input length, target-item count, target-word count, and quantile
indicators; all-skills splits additionally balanced the five component-label
counts, and merged splits balanced occupation membership. IDs used during
prompt development were kept out of test whenever feasible. This was feasible
for 17 configurations; IT--all necessarily retained five such IDs because the
clean non-prompt pool was smaller than the fixed test size. Excluding those
five IDs changed macro $F_1$ by at most 0.0033 and did not change the principal
domain conclusions. The implementation groups by identifier, not by normalized
text, so the paper must not claim text-level grouping.
\end{NewBlock}

\section{BERT implementation}
\begin{OldBlock}
Training and validation use description only, final test combines headline and
description, and ordinary cross-entropy loss is minimized.
\end{OldBlock}
\begin{NewBlock}
The same model input was used in training, validation, and test: the stripped
headline and description joined by a newline. Annotated strings were weakly
aligned to case-insensitive contiguous source spans, tokenized into windows of
at most 512 subwords with stride 128, and encoded as B-SKILL, I-SKILL, and O.
All 18 BERT configurations used weighted token cross entropy. Weights were
computed only from the training partition as
$w_c=\min(10,\max(1,\sqrt{N_O/N_c}))$, with $w_O=1$ and padding ignored.
Validation and test decoding used evaluation mode; no CRF was used.
\end{NewBlock}

\section{BART implementation}
\begin{OldBlock}
Inputs and targets are truncated to 1,024 and 96 tokens. Each long-text chunk
is paired with the complete advertisement-level target list. Training uses the
description, while validation and test combine headline and description.
\end{OldBlock}
\begin{NewBlock}
The same headline--description input was used for all partitions. Inputs longer
than 1,000 tokenizer tokens were divided into overlapping chunks with a
160-token overlap. Each gold skill was assigned to every chunk containing its
normalized contiguous token sequence; if no chunk contained it, the skill was
assigned deterministically to the chunk with the largest token-set overlap.
The serialized target and generated continuation were limited to 512 tokens.
Validation used beam width two; final test generation used beam width six and
a no-repeat trigram constraint. Chunk predictions were merged and exactly
deduplicated before the shared prediction filter and scorer were applied.
\end{NewBlock}

\section{Winner claims}
\begin{OldBlock}
Fine-tuned BERT led 11 of 18 cells; prompted models led seven; GPT led
distinct-skill extraction for journalists and merged data; prompted models
were strongest on both distinct and nice-to-have skills on average.
\end{OldBlock}
\begin{NewBlock}
Under the primary exact metric, BERT led 12 of 18 domain--skill cells, Gemini
led three, GPT led two, and BART led one; Claude led none. Under the secondary
containment metric, BERT led 13 cells, Gemini four, and Claude one; GPT and BART
led none. Thus, BERT led all-skills and hard-skills in every domain under both
metrics, but the exact and containment views differ for some label-specific
cells. Averaged across domains, BERT had the highest exact and containment score
for distinct skills, whereas Gemini had the highest score for nice-to-have
skills. The supported higher-level conclusion is narrower: prompted-model wins
under containment were concentrated on distinct or nice-to-have cells (four of
five prompted wins), not that prompted models were uniformly best on both
labels.
\end{NewBlock}

\section{Task-unadapted controls}
\begin{OldBlock}
The abstract, Results, Discussion, and Conclusion quantify large before--after
fine-tuning gains using the legacy controls and state that the current
academic-v2 models improve by those amounts.
\end{OldBlock}
\begin{NewBlock}
The academic-v2 release contains 36 fine-tuned runs, 36 task-unadapted
controls, and 54 aligned prompted-model configurations. Every control matches
the corresponding fine-tuned run in canonical test-identifier order, gold
labels, normalization, prediction filtering, and centralized scoring. The
BERT control applies a fixed-seed random BIO classification head to the
pretrained encoder; the BART control uses the pretrained denoising checkpoint
without task-specific updates. Neither control reads train or validation data.
They are therefore task-unadapted controls, not architecture-matched zero-shot
systems. Averaged across the 18 domain--skill configurations, exact normalized
macro $F_1$ increased from 0.034 to 0.440 for BERT and from 0.00005 to 0.334
for BART. Fine-tuning improved this primary metric in all 36 paired
configurations.
\end{NewBlock}

\section{Filtering, unsupported output, and fairness}
The shared filter removed 4.71\% of raw BERT items, 0.01\% of BART items, and
approximately 0.05\% of prompted-model items. This difference must be
disclosed even though every system used the same rule files. Unsupported-item
rates were structurally zero for source-bound BERT, 4.02\% for BART, 0.48\%
for GPT, 1.00\% for Gemini, and 5.69\% for Claude. These rates are useful
diagnostics but are not a like-for-like architectural score because BERT cannot
generate text outside the source.

All five systems share test identifiers, gold lists, normalization, filtering,
and scoring. This establishes arithmetic comparability, not equivalence of
training resources: BERT and BART receive supervised parameter updates, while
the commercial systems use prompts developed with labeled examples. The paper
must call this a comparison of adaptation and resource regimes, not a fair
architecture-only experiment.

\section{Limitations that should remain explicit}
Only one training/data seed was run, and retained commercial outputs contain no
repeated API calls. Small score differences therefore remain descriptive. The
surviving LLM workbooks do not preserve exact provider snapshot IDs, raw API
responses, retry histories, or original format failures. Twenty-two unique IDs
show whitespace or punctuation tokenization differences between retained LLM
text and canonical text, but all differences disappear after removing
whitespace and punctuation. Per-skill datasets contain only advertisements with
at least one annotation for that label; performance on genuinely negative
advertisements is therefore not estimated. Finally, IDs are split independently,
so equal text under different IDs is not prevented from crossing partitions.
